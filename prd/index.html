01

개요

Summary

KUNUK은 AI 필름·그래픽·비주얼 디렉션 작업을 모아 보여주는 1인 포트폴리오 사이트다.

한 줄 정의(one-liner): “피드(feed)가 아니라 아카이브(archive)처럼 읽히는, 차갑고 인더스트리얼한 작업 색인(index).” A24의 절제된 감도를 참조하되(reference), 카탈로그 코드(catalog code)와 모노스페이스(monospace) 표기라는 고유 언어로 차별화한다.

02

문제와 목표

Problem & Goals
Problem
갱신에 코드가 필요했다
기존 사이트는 정적 HTML 한 장(single static page)이라, 작업을 하나 추가하려면 매번 마크업(markup)을 직접 고쳐야 했다. 비개발자 운영이 불가능한 구조.
Goal
코드 없이 운영, 무료 유지, 고유한 감도
① 관리자 화면·인라인 편집으로 코드 없이 작업 추가 ② 호스팅(hosting) 비용 0원 유지 ③ 참조는 하되 통째로 베끼지 않는 시각 언어.
03

사용자

Target Users / Personas
Primary Persona
운영자 — 본인
비개발자. 톱니바퀴 → 비밀번호 → 홈페이지 위에서 바로 사진·제목·상태를 고치는 인라인 편집 모드(inline edit mode)로 사이트를 관리한다.
Secondary Persona
방문자 — 잠재 클라이언트 / 협업자
모바일 비중이 높다. 작품을 빠르게 훑고(scan) 인상을 남기는 게 목적. 스와이프(swipe)와 세로 스텝 스크롤 경험이 핵심.
04

범위

Scope

In Scope — 포함

  • 히어로(hero) 작업 색인 + 스텝 스크롤
  • Index 아카이브 페이지
  • CMS 관리자 + 인라인 편집
  • 다국어(i18n) 5개 언어
  • 라이트/다크 테마(theme)

Out of Scope — 제외

  • 결제·이커머스(e-commerce)
  • 회원 가입·로그인 회원제
  • 블로그·글쓰기 CMS
  • 사이트 내 검색(search)

기능 요구사항

Functional Requirements — 우선순위(MoSCoW) · 상태
R01
히어로 스텝 스크롤
최상단에서 스크롤/스와이프 시 페이지가 넘어가지 않고 작업을 1→4로 한 단계씩(step) 전환. 스크롤 하이재킹(scroll hijacking).
MustLive
R02
카탈로그 코드 페이저
A24의 “1/6” 대신 NUK—001 코드가 플립시계(split-flap)처럼 굴러가며 위치를 표시. 눈금자(ruler) 틱과 결합.
MustLive
R03
블러 디졸브 레이어 전환
배경 레이어(layer) 교체 시 흐릿(blur)→선명으로 초점이 맞으며 크로스페이드(crossfade). 영상 용어로 디졸브(dissolve).
ShouldLive
R04
모바일 스와이프 · Index 글라이드
가로 스와이프로 작업 전환, 마지막 작업 후 스무스 스크롤(smooth scroll)로 Index에 부드럽게 핸드오프(handoff).
MustLive
R05
CMS 관리자
Decap CMS + GitHub OAuth 백엔드(backend). 사진 업로드 시 저장소에 커밋(commit)되고 자동 재배포(auto-deploy).
MustLive
R06
홈페이지 인라인 편집 모드
관리자 페이지가 아니라 실제 화면 위에서 틀·제목·상태·연도를 클릭해 수정. GitHub API로 직접 커밋.
ShouldLive
R07
다국어 i18n
EN·KO·JA·ZH·FR 5개 언어. 브라우저 언어 자동 감지(locale detection) + 수동 전환.
ShouldLive
R08
라이트 기본 · 서클 리빌 테마
라이트 테마 기본값. 전환 시 뷰 트랜지션 API(View Transition API)로 버튼에서 원형(circular reveal)이 퍼짐. 선택은 localStorage에 기억.
ShouldLive
R09
메뉴 오버레이 내비게이션
좌측 상단 MENU → 전체화면 오버레이 내비(overlay navigation): Home / Index / Contact.
MustLive
R10
반응형 레이아웃
데스크톱은 호버(hover), 모바일은 스와이프/탭 기반의 적응형(responsive) 레이아웃. 페이저·아이브로우는 모바일 전용 조판.
MustLive

비기능 요구사항

Non-Functional Requirements (NFR)
Cost
$0 운영
Vercel 무료(Hobby) 플랜. 정적 자산(static assets) 위주라 무료 한도 안에서 무기한 운영.
Performance
즉시 로드
이미지 지연 로딩(lazy loading), FOUC(무스타일 깜빡임) 방지 프리페인트 스크립트.
Accessibility
키보드·모션 배려
포커스 상태(focus state) 노출, prefers-reduced-motion 존중.
Compatibility
모던 브라우저
View Transition 미지원 브라우저는 자동 폴백(fallback)으로 즉시 전환.

09

디자인 원칙

Design Principles

아카이브 > 피드. 무한 스크롤 타임라인이 아니라, 번호가 매겨진 카탈로그처럼 읽히게 한다.

모노스페이스 카탈로그 코드. 메타데이터(연도·상태·코드)는 전부 모노스페이스로 — 도면·특허 문서의 정밀함.

단일 액센트. 인터내셔널 클라인 블루(IKB) 하나만 강조색으로. 나머지는 무채색으로 조용하게.

절제된 모션. 효과는 의미가 있을 때만. 과한 애니메이션은 오히려 ‘AI가 만든 느낌’을 준다.

용어집

Glossary — 탑다운으로 배우는 웹 용어
PRD
Product Requirements Document. 무엇을·왜·어떤 기준으로 만들지 합의하는 문서.
Hero
페이지 최상단의 전체화면 대표 영역.
Scroll hijacking
스크롤을 가로채 다른 동작(작업 전환)으로 바꾸는 기법.
Pager
현재 몇 번째인지 알려주는 위치 표시 장치.
Dissolve / Crossfade
한 화면이 흐려지며 다음 화면이 겹쳐 나타나는 전환.
Eyebrow
제목 위에 붙는 작은 라벨(상태·분류).
IA
Information Architecture. 페이지·콘텐츠의 구조와 배치.
MoSCoW
우선순위 분류: Must / Should / Could / Won’t.
CMS
Content Management System. 코드 없이 콘텐츠를 편집하는 시스템.
Serverless function
서버를 직접 운영하지 않고 요청 시에만 실행되는 함수.
i18n
internationalization. 다국어 지원(i···18글자···n).
View Transition API
화면 전환에 애니메이션을 입히는 브라우저 기능.
FOUC
Flash of Unstyled Content. 스타일 적용 전 잠깐 깜빡이는 현상.
CI/CD
코드 푸시 → 자동 빌드·배포로 이어지는 파이프라인.
Source of truth
서로 다를 때 기준이 되는 단일 원본.
Fallback
주 기능이 안 될 때 대신 작동하는 대체 동작.
